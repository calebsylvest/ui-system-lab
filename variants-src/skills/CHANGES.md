# Fieldwork: Interface skills variant

This variant applies Jakub Krehel's `better-interface` skill, which coordinates `better-accessibility`, `better-layout`, `better-writing`, `better-typography`, `better-colors` and `better-ui`. The page got a full review: recon first, then each domain in the skill's order, with findings ranked by severity. After that, I implemented every finding the rules support, choosing the cheapest fix that worked in this order: delete, use the platform, reuse, correct the value, add. Content, sections, data and interactions are unchanged except for copy edits that `better-writing` calls for. No dependencies were added.

**Recon:** Vite, React 19, Tailwind v4 and hand-written shadcn/ui (new-york) on Radix, with lucide icons and sonner toasts. Tokens live in `src/index.css`, and dark mode uses the `.dark` class. The project has no convention docs (no CONTRIBUTING, AGENTS or design-system doc). The README is the Vite template.

**Verification:** `npm run build` passes. I grepped the built CSS to confirm that the new utilities were emitted, including `not-aria-disabled`, `motion-safe:*`, the logical insets and `translate-x-(--progress-rest)`. I measured contrast pairs with an OKLCH-to-sRGB WCAG 2 script that composites alpha over the actual background. I did **not** check the rendered page in a browser: there were no keyboard walk, no 320px/200% zoom check and no screen-reader pass, because the device VM's server can't be reached from the browser pane.

## Findings not implemented

- **The nav search is still hidden below 640px** (a 320px trigger). It needs a search sheet or a dedicated route, which would be a new feature.
- **The active tab is shown only by a white chip on `#f5f5f5` plus shadow-sm in light mode.** Muting the inactive tab text would add a cue, but muted-foreground on muted measures 4.34:1 and would fail. I flagged it instead of redesigning the tabs.
- **"Delete" (project menu and Controls) has no confirmation or undo.** It does have the distinct destructive treatment the trigger allows, and the button does nothing in this demo, so a confirmation dialog would be a new feature.
- **Showcase labels such as "Primary", "Outline", "Plain toast" and "Small" aren't verb-first.** They name the variant being demonstrated, so I kept them.
- **The token names follow shadcn (`--primary`, `--accent` as hover).** That clashes with better-colors' naming grammar, but renaming is a migration across every component, and the skill says to match the project's system.
- **The 16px table checkboxes are under 24px.** The 2.5.8 spacing exception covers them, so I didn't add hit-area pseudo-elements.
- **The 8px gaps between bordered buttons and the letter-spacing on 24px headings are left alone.** Both are heuristics, and the project has an established density.
- **Exit animations keep tw-animate's zoom/fade** instead of the skill's blur + 12px exit recipe. Matching that recipe would mean rewriting the overlay motion language; I only shortened the exit to 150ms.
- **Rendered checks are Not verified:** keyboard walk, 320px/200% zoom, RTL mirror, screen reader and dark-mode rendered contrast.
